# agy-statusline — agent operations guide

Two independent deliverables share one telemetry core:

| Component | What it is | Where it runs |
| :--- | :--- | :--- |
| `agy-statusline` | Zig single binary, zero-dependency CLI statusline (`tok/s`, cache hit, context, quota reset) | Antigravity CLI, via the official `statusLine` extension protocol |
| `AGY Desktop Status` | Native Zig sidecar + one embedded HTML panel | Antigravity 2.0 Desktop right pane, via the official `SIDECAR_UI_ENTRYPOINT_AUX_PANE` plugin API |

## Non-negotiable constraints

1. **Read-only, zero network.** Only read `~/.gemini/antigravity/…` (SQLite `conversations/*.db`, `brain/*/logs/transcript.jsonl`), the hook state file, and `quota.json`. Never write to Antigravity's database or config, never call internal RPC, never send telemetry anywhere.
2. **Never restart the host from inside it.** If you are running inside Antigravity and an install requires a host restart, tell the user to restart the app. Do not `pkill`/`killall` Antigravity, do not relaunch it, and do not script a "restart for you" step — it would terminate the window hosting the conversation.
3. **Never hand-edit `desktop-panel/dist/index.html`.** It is generated. Edit `ui/src/*` and rebuild (see below), otherwise `tests/test_assets.py` fails and the panel silently keeps serving the old bundle.
4. **Never edit `desktop-panel/manifest.json` by hand.** It is regenerated by the UI build.
5. Antigravity's own data must stay untouched: the plugin only adds files under `~/.gemini/config/plugins/agy-desktop-status/`.

## Key paths

| Item | Path |
| :--- | :--- |
| CLI binary | `~/.gemini/antigravity-cli/agy-statusline` |
| CLI statusline config | `~/.gemini/antigravity-cli/settings.json` (`statusLine`) |
| Panel plugin | `~/.gemini/config/plugins/agy-desktop-status/` |
| Panel settings (preserved on uninstall) | `~/.gemini/agy-statusline/config.json` |
| Quota snapshot written by the CLI | `~/.gemini/agy-statusline/quota.json` |
| Hook state (written by the panel's own hook) | `<plugin data>/active_session.json` |

## Install / upgrade / remove

```sh
# all components (also works via `curl … | bash -s -- …`)
./install.sh
./install.sh --cli-only
./install.sh --panel-only

# diagnosis: human output, or machine-readable with stable codes
./install.sh --doctor
./install.sh --doctor --json

# removal (plugin dir + CLI binary; config.json and quota.json are kept)
./install.sh --uninstall
```

`--doctor --json` is the contract to branch on. Exit code is `0` only when `ok` is `true`.

| Code | Meaning / action |
| :--- | :--- |
| `cli_missing` / `panel_missing` / `backend_missing` | Not installed; run the matching installer |
| `cli_quarantine` / `backend_quarantine` | `xattr -dr com.apple.quarantine <dir>` |
| `cli_signature_invalid` / `backend_signature_invalid` | Rebuild or reinstall; macOS will SIGKILL the binary |
| `cli_not_runnable` / `backend_not_runnable` | Usually Gatekeeper; clear quarantine first |
| `version_mismatch` | `plugin.json` and the bundled backend disagree; reinstall the panel |
| `mdm_requires_developer_id` | Managed Mac rejects ad-hoc builds; needs IT allow-listing by CDHash |
| `statusline_not_configured` | CLI installed but `settings.json` has no `statusLine` |

## Configure without restarting

`~/.gemini/agy-statusline/config.json` is re-read by the sidecar when its file signature changes, so edits apply within one poll cycle (≈1–3 s). Keys:

`enabled`, `layout` (`compact`|`detailed`), `pollSec`, `lowSpeedWarnTokS`, `thresholds.{waitSec,stallSec,toolGraceSec}`, `modules.{session,quota,history,context,models}`, `debug`.

Defaults live in `config.example.json`; the parser clamps every value, so an out-of-range edit degrades instead of breaking the panel. Set `debug: true` to get `session.evidence` in the JSON for troubleshooting.

## Where behaviour lives

| Question | File |
| :--- | :--- |
| Why is the chip blue/yellow/red, and what is the sentence under it? | `desktop-panel/native/session.zig` (pure state machine, no I/O) |
| How are thresholds/modules parsed and echoed? | `desktop-panel/native/settings.zig` |
| Where do tok/s, context, cache, quota come from? | `desktop-panel/native/telemetry.zig` |
| Why are some numbers `--`, and why is there a "数据不完整" banner? | `sourcesValue()` in `telemetry.zig` — per-source state plus stable reason codes |
| HTTP routes, auth token, CLI modes | `desktop-panel/backend.zig` |
| Chip rendering, layout, module hiding, polling | `desktop-panel/ui/src/app.ts` (+ `template.html` CSS) |
| CLI statusline output | `main.zig` |

`session.zig` and `settings.zig` take plain values and return plain values on purpose: the UI must never re-derive a threshold, and the state machine must stay testable without a database.

## Build and verify

```sh
# backend (Zig 0.14.1 + system C compiler + sqlite3)
cd desktop-panel && ./build.sh

# panel UI: regenerates dist/index.html AND manifest.json
cd desktop-panel/ui && npm install && npm run build

# CLI binary
./build.sh
```

Checks, in the order that catches the most first:

```sh
cd desktop-panel/ui && npx tsc --noEmit -p tsconfig.json
cd desktop-panel/tests && python3 -m unittest test_native test_session test_assets test_desktop_panel test_version test_installers
cd desktop-panel/tests && node test_sidecar.mjs      # needs Node + ui/node_modules
```

Rebuild order matters: **UI first, then backend** (`build.sh` embeds `dist/index.html`, and `test_native` asserts the served HTML equals the committed bundle).

## Troubleshooting matrix

| Symptom | Likely cause | Check |
| :--- | :--- | :--- |
| Panel is blank | Backend refused to start (Gatekeeper) or quarantine | `--doctor --json` → `backend_not_runnable` / `backend_quarantine` |
| Panel shows "已关闭" | `enabled: false` in `config.json` | Read the file, flip to `true` |
| Chip stuck on「无 Hook」 | Hook events never arrived (plugin just installed, or hooks.json missing) | Restart Antigravity once; verify `hooks.json` in the plugin dir |
| Banner "数据不完整 · 数据库被占用" | Another window holds an exclusive lock on the conversation DB, or the file is unreadable | `sources.db` in `/api/status`: `locked` self-heals on the next poll; `unreadable` / `missing` needs attention |
| Chip shows「异常」repeatedly with the same reason | `terminationReason` from a finished turn still inside its 180 s TTL | Expected; it decays to 就绪 on its own |
| Live speed stays `--` | No active step row; the turn already finished | Compare `live.active` in `/api/status` |
| Quota tab empty | `agy` CLI has not rendered since install (nothing to snapshot) | Run the CLI once, or accept "no data" |
